# AWS学習ゲーム v4 仕様書

## 1. シリーズの核

v4 は「案件要件を読み、AWSサービスを選び、選択理由を短く復習する」シリーズの核を保ちながら、1回のプレイ全体に意味が残るキャンペーン型へ作り直す。

- 案件・障害・制約を読み、適切なAWSサービスを選ぶ
- 機能、可用性、セキュリティ、性能、コスト、運用負荷の6軸で結果を返す
- 正解、支援、罠、互換不可、シナジー、アンチパターンを明示する
- 日本語、ダークUI、青系アクセント、軽い絵文字でシリーズの雰囲気を保つ
- 誤答した正解サービスを復習候補として後続案件に混ぜる

## 2. v3の問題点分析

v3 はテンポを優先したが、プレイヤーから見ると「各ラウンドの正解を集めるだけ」になりやすかった。

- 1プレイの外側に目的がなく、クリア後の継続動機が弱い
- 候補8枚・最大3選択で、迷う余地が少ない
- 案件タイプがほぼ同じで、知識を別文脈へ転用しにくい
- 正解/罠/シナジーのデータ量が少なく、中級語彙へ広がりにくい
- 誤答したサービスが後で再登場する仕組みがない

v4 ではキャリア進行、持続リソース、章末ボス案件、復習フラグでこの弱点を補う。

## 3. v4のコンセプト一言、ターゲット体験

コンセプト: **AWS案件を解いて昇進する、キャンペーン型クラウド設計キャリア。**

ターゲット体験:

- 新人からアーキテクトまで、章をクリアして肩書きを上げる
- 評判、予算、信頼、SLAクレジットが将来のプレイ可能性に効く
- 10〜16枚の候補から3〜6枚を選び、似たサービスの違いを考える
- incident、cost_cut、harden、migrate など複数の文脈で同じサービスを学ぶ
- 失敗した正解サービスが復習対象として次の案件候補に出やすくなる

## 4. ゲームの基本ループ

1. タイトルから「続きから」または「最初から」を選ぶ
2. キャリア画面で現在の肩書き、リソース、解放章を確認する
3. 章を開始し、4〜5件の案件を連続で解く
4. 各案件で候補サービス10〜16枚から上限枚数まで選ぶ
5. 提出または時間切れで採点し、6軸評価と理由を読む
6. 章末でリソース変化、昇進、次章解放、復習テーマを確認する
7. リソースが危険域を下回るとゲームオーバー演出を表示し、最初からやり直せる

## 5. メタ進行

持続リソース:

- 評判: 章クリアと高ランクで増え、低スコアや罠選択で減る
- 予算: cost_cut 成功で増え、過剰構成や罠で減る
- 信頼: セキュリティ/コンプラ案件の成功で増え、重大な不足で減る
- SLAクレジット: incident、可用性案件の成功で増え、障害対応失敗で減る

昇進:

- 新人: ネットワークとWeb配信章
- ジュニア: データ層とイベント駆動章
- シニア: セキュリティ、監視、コスト章
- アーキテクト: 複合ボス章

いずれかのリソースが0以下になるとゲームオーバー。章をクリアすると次章が解放され、一定章数で肩書きが上がる。

## 6. 評価ルール

ラウンドスコア:

- 必須サービス: 1件 +18〜22点
- 支援サービス: 1件 +8〜10点
- 必須全的中: +10点
- 罠サービス: 1件 -12〜20点
- 互換不可の同時選択: 1件 -14〜18点
- シナジー: 1件 +6〜10点
- アンチパターン: 1件 -8〜16点
- 時間ボーナス: 残り秒数に応じて最大8点

6軸評価:

- 案件タイプごとの重みを持つ
- サービスの軸寄与、シナジー、罠、未選択の必須サービス、互換不可で補正する
- 0〜100に丸め、ランクは S/A/B/C/D で返す

章クリア:

- 章平均70点以上、かつ全リソースが1以上でクリア
- ボス案件は60点未満なら章平均に関係なくリソース減少が大きい
- クリア時は次章解放と肩書き更新を行う

## 7. 学習効果の担保

- 45種類のAWSサービスを初学者〜中級者の範囲で扱う
- 32件の案件を業種とタイプで散らす
- 各案件に required/support/trap/conflict/antiPattern を持たせる
- 結果画面で不足、余計、罠、互換不可、シナジーを分けて表示する
- 誤答した required サービスを reviewFlags に記録し、次回以降の候補に混ぜる
- 章末で苦手軸と復習サービスを提示する
