# Codex 作業指示書 — 犬の足跡付き砂浜シミュレーター

> 本書は **Codex が実装作業を行うための指示書**です。設計の根拠・仕様は必ず同ディレクトリの `DESIGN.md` を参照してください。本書は「何を・どの順で・どう報告するか」を定めます。

---

## 0. 体制と役割分担（最重要）

| 役割 | 担当 | 責務 |
|------|------|------|
| **管理・統括** | Claude | 全体管理、設計判断、受け入れ確認、相互レビュー、マイルストーン承認 |
| **実装** | Codex | 設計書に基づくコード編集・実装・自己テスト・自己レビュー |

- **編集作業（コードの追加・変更・削除）は必ず Codex が実施する。** Claude は原則コードを直接編集せず、レビューと指示・統括に徹する。
- Codex は各マイルストーン完了時に Claude のレビューを受け、**承認を得てから次へ進む**（相互レビュー）。

---

## 1. Codex への基本指示（必ず守ること）

1. **設計書 `DESIGN.md` を唯一の仕様の正とする。** 解釈に迷ったら自己判断で大きく逸脱せず、§7 の手順で Claude に報告・確認する。
2. **マイルストーン単位（M1〜M8）で実装する。** 一気に全部作らない。各 M の完了ごとに自己テスト → 自己レビュー → Claude へ報告。
3. **以下のいずれかが起きたら、ただちに作業を止めて Claude に報告する：**
   - マイルストーンが完了したとき（成果と次の提案を添えて報告）。
   - 設計書どおりに実装できない／設計に矛盾・抜けを見つけたとき。
   - 想定外の技術的問題（ビルド不能、WebGPU/WebGL2 非互換、パフォーマンス未達など）。
   - 設計判断が必要な分岐（複数の実装方針があり優劣が決めきれない）。
4. **報告は §7 のフォーマットに従う。** 「完了」または「問題発生」を明示する。
5. **勝手にスコープを広げない。** 追加機能・大規模リファクタは事前に Claude の承認を得る。
6. **コミットはマイルストーン単位**で、わかりやすいメッセージで行う。ブランチは `claude/threejs-sand-footprint-sim-ywj005` を使用（指定外ブランチへは push しない）。

## 2. 成果物とディレクトリ（DESIGN.md §13 準拠）

`sand-footprint-sim/` 配下に Vite + TypeScript + Three.js プロジェクトを構築する。

```
sand-footprint-sim/
  index.html
  package.json
  vite.config.ts
  tsconfig.json
  src/
    main.ts
    scene/{createRenderer,createCamera,createLights}.ts
    sand/{SandPlane,sandShader,sandParams}.ts
    footprints/{FootprintSystem,pawStamp,footprintTypes}.ts
    interaction/PointerTrail.ts
    effects/WashWave.ts
    ui/createGui.ts
    styles.css
```

- 既存の `DESIGN.md` はこのディレクトリにあるため、上書き・削除しないこと。

---

## 3. 技術制約（DESIGN.md §2 準拠 / 逸脱厳禁）

- **TypeScript + Vite + Three.js**、React 不使用。
- **WebGPURenderer 優先、失敗時 WebGLRenderer(WebGL2) フォールバック。**
- シェーダーは **TSL / node materials を第一候補**（単一記述で両バックエンド対応）。TSL で困難な箇所が出たら勝手に GLSL 二重化せず Claude に相談。
- UI 調整は **lil-gui**。
- **外部アセット禁止**（足跡マスク・砂ノイズ等はプロシージャル生成）。後差し替え可能な構造にする。
- iPhone Safari で **30FPS 前後**を目標。固定長15バッファ、毎フレームの new 禁止。

## 4. マイルストーンと完了条件（DESIGN.md §16 準拠）

各 M は「完了条件を満たし、ローカルで `npm run dev` がエラーなく動く」ことを確認してから報告する。

| M | 内容 | 完了条件（Codex が自己確認） |
|---|------|------------------------------|
| **M1** | 足場構築：Vite+TS+Three、Renderer(WebGPU→WebGL2分岐)、Orthographicカメラ、全画面リサイズ、フラットな砂平面表示 | ビルド成功・画面全体に平面が表示・リサイズ追従・どちらのバックエンドで動いたかログ出力 |
| **M2** | 砂質感：sandShader（ノイズ法線・色・ラフネス）、ライティング、トーンマッピング | 砂らしい質感・斜光で陰影・トーンマッピング適用 |
| **M3** | 入力：PointerTrail（タッチ/マウス統一、座標変換、方向平滑化、stride判定） | PC/スマホ両方でドラッグ位置がワールド座標に正しく変換される |
| **M4** | 足跡：pawStampプロシージャル生成、HeightField焼き込み、変位反映、左右交互・向き追従 | なぞると足跡が凹み・向き追従・左右交互に出る |
| **M5** | 時間変化：固定長15バッファ・age・decay・darkening・重なり | 新しい足跡ほど深く濃い／古いと浅く薄い／重なる |
| **M6** | GUI：lil-gui で全11パラメータ＋Washボタン＋性能プリセット | 全パラメータが見た目に反映 |
| **M7** | Wash：WashWave 演出と足跡ワイプ | Washで波が流れ足跡が消え初期状態に戻る |
| **M8** | 最適化：30FPS調整、解像度プリセット詰め | 想定負荷でフレーム落ちが過度でない |

> パラメータ一覧（11個）・物理的意味は **DESIGN.md §6** を参照。受け入れ条件は **DESIGN.md §15** を参照。

## 5. コーディング規約

- TypeScript strict。`any` は原則禁止（やむを得ない場合はコメントで理由を明記）。
- モジュール責務は **DESIGN.md §14 の API スケッチ**に沿う。公開 API を変える場合は事前相談。
- 関数・変数名は意味のある英語。コメントは要点のみ（過剰なコメント不要）。
- 毎フレーム処理（ループ内）での **オブジェクト生成・配列確保を避ける**。
- マジックナンバーは `sandParams.ts` か定数にまとめる。

---

## 6. 自己テスト・自己レビュー（報告前に必ず実施）

各マイルストーン報告の前に、Codex は以下を自分で実施する：

1. **ビルド／起動確認**: `npm install` → `npm run dev` がエラーなく動く。`npm run build`（あれば）も通す。
2. **型チェック**: `tsc --noEmit` が通る。
3. **動作確認**: 当該 M の完了条件を満たすか目視/ログで確認。
4. **自己レビュー観点**:
   - 設計書からの逸脱はないか。
   - 毎フレームの不要なアロケーションはないか。
   - WebGL2 フォールバック経路を壊していないか。
   - 固定長15・最大足跡数の制約を守っているか。
5. 問題があれば直してから報告。直せない問題は「問題発生」として報告。

## 7. 報告プロトコル（Claude への報告フォーマット）

Codex は **マイルストーン完了時** および **想定外の問題発生時** に、必ず以下の形式で Claude に報告すること。

### 7.1 完了報告テンプレート
```
【報告区分】完了
【マイルストーン】M_ : <名称>
【実施内容】<追加/変更したファイルと要点を箇条書き>
【自己テスト結果】build: OK/NG / tsc: OK/NG / 動作確認: <結果>
【設計書との差分・判断】<あれば。なければ「なし」>
【次の提案】<次に進むべきM / レビュー依頼事項>
【コミット】<コミットハッシュ or メッセージ>
```

### 7.2 問題発生報告テンプレート
```
【報告区分】問題発生
【発生箇所】M_ / <ファイル・機能>
【事象】<何が起きたか。エラーメッセージがあれば添付>
【原因の仮説】<分かっている範囲で>
【試したこと】<対処の試行>
【相談・選択肢】<Claudeに判断してほしい点。複数案があれば併記>
【現在の状態】<ビルド可否・どこまで動くか>
```

- **完了したら必ず報告し、Claude の承認を待ってから次の M に進む。**
- **思わぬ問題が発生したら、作業を続けて傷を広げず、まず報告する。**
- 報告は簡潔に。長大なログは要点を抜粋する。

---

## 8. 相互レビューの流れ

1. Codex: マイルストーン実装 → 自己テスト・自己レビュー → §7.1 で完了報告。
2. Claude: 報告と差分をレビュー。指摘があれば修正指示、なければ承認。
3. Codex: 指摘対応（あれば）→ 再報告。承認後、次の M へ。
4. これを M1→M8 まで繰り返す。

---

## 9. やってはいけないこと（禁止事項）

- 設計書・本書を無断で書き換える / 大きく逸脱する。
- スコープ外の機能追加・大規模リファクタを無断で行う。
- 外部アセット（画像・モデル等）を取り込む（プロシージャル原則に反する）。
- 指定ブランチ以外へ push する / PR を勝手に作る。
- 完了・問題発生を報告せずに次工程へ進む。
- 毎フレームでの new / 大量アロケーションを残す。

---

## 10. 最初に着手すること

1. 本書と `DESIGN.md` を読み込む。
2. **M1（足場構築）から開始**する。
3. M1 完了条件を満たしたら §7.1 で Claude に完了報告し、承認を待つ。

不明点・設計の矛盾を見つけた場合は、実装を進める前に §7.2 で Claude に報告すること。
